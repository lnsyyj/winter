# 售前工程师（Pre-sales / 解决方案架构师）

> 岗位线：**业务线** — 把软件卖出去、让客户满意 ｜ 原文第 **12** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

销售的技术搭档——用技术帮销售搞定单子，同时避免销售乱承诺、研发背锅。

## 核心职责

- 跟销售去客户现场演示产品、回答技术硬问题
- 把客户模糊诉求写成解决方案 / 投标文档
- 搭 Demo 环境，证明「真的能跑」
- 对内把真实需求带回给产品经理

## 常见产出

- 解决方案
- 投标书 / 技术方案
- Demo 环境与演示脚本
- 技术评估报告

## 在本项目中的落位（Ceph 管理平台）

- 最容易出的错：把「管理平台」讲成「存储产品」，导致验收时客户拿数据面性能说事（权衡分析 B1）。
- 建议产出一份「能力边界与不承诺清单」，与合同附件一致：管的是生命周期，不管数据路径。
- Demo 必须能演示异常路径——「建集群失败后重试成功」比「一次成功」更有说服力。
- 客户现场常问的三个问题要准备好答案：要不要停业务？支持离线吗？Agent 权限多大？
