## 2. 前置条件（现场确认表）

| 项 | 要求 | 确认 |
| --- | --- | --- |
| 管理节点 | OS CentOS Stream 9，≥ 10C / 16G / 250G（见 SRE §1） | ☐ |
| 被管节点 | CentOS Stream 9、podman、≥3 块可用数据盘、NTP 同源 | ☐ |
| 网络 | 管理面 443 对外；被管节点可**出站**到管理面；无入站要求 | ☐ |
| 离线 | 无公网时，镜像经离线包导入；镜像仓库可对接客户现有 | ☐ |
| 凭据 | 管理员账号、ceph 接入凭据、证书签发方式 | ☐ |
| 时间 | 全节点时间同步（漂移 > 阈值会导致 cephadm 失败） | ☐ |

## 4. 回滚

| 场景 | 动作 |
| --- | --- |
| 管理面部署失败 | 停止 pod / compose，保留数据卷，回滚到上一版本 bundle；**不触碰被管节点与 Ceph** |
| Server 升级失败 | 回滚 Server 镜像；数据库 migration 需保证向后兼容 |
| Agent 升级失败 | 分批回滚二进制，Agent 需兼容 N-1 协议 |
| 建集群中途失败 | **不自动回滚**（不可逆，见权衡分析 B5）；按平台「失败步骤 / 清理任务」或人工清理磁盘后重跑 |
| 解除纳管 | 删除集群记录 + 删除凭据 + 吊销 Agent 证书 + 写审计；**不改动 Ceph 集群本身** |

> 最重要的回滚原则：任何情况下，控制面操作都不得成为数据面故障的来源。拿不准就先停任务下发（全局熔断）。
