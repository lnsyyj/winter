# 产品运营（Product Operations）

> 岗位线：**产品线** — 决定「做什么、给谁用」 ｜ 原文第 **2** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

产品上线后的「拉长尾」选手——产品经理负责「生出来」，运营负责「活得好」。

## 核心职责

- 盯日活 / 留存 / 转化等使用数据，判断产品是否真的被用起来
- 做活动、写推送、组织上手培训
- 回应用户反馈，把高频抱怨收敛成需求
- 盘活存量用户，让已纳管的集群继续留在平台上

## 常见产出

- 活动方案 / 推广计划
- 数据报告 — 使用率、活跃度、功能采纳度
- 推送与内容（公告、版本说明）
- 用户反馈汇总

## 在本项目中的落位（Ceph 管理平台）

- 本平台是 To B 运维工具，「运营」的落点是**内部推广与采纳度**，不是拉新投放。
- 核心指标建议：纳管率（已纳管集群 / 全部集群）、周活跃运维人数、功能使用分布、任务成功率。
- 与客户成功的分工：产品运营看整体使用与增长，客户成功盯单客户续约与增购。
- 数据可直接取自平台自身 API（集群数、任务数、活跃用户），不必等埋点体系。
