# 产品经理（PM / Product Manager）

> 岗位线：**产品线** — 决定「做什么、给谁用」 ｜ 原文第 **1** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

产品的「迷你 CEO」——不写代码，但对产品全生命周期负总责。

## 核心职责

- 收集客户痛点，把模糊需求翻译成明确的需求文档与原型图
- 排优先级，与研发、测试、设计反复对齐
- 用用户故事表达需求：作为谁 / 想要什么 / 以便怎样
- 上线后看数据、听反馈，决定下一轮迭代

## 常见产出

- PRD（需求文档）— 解决什么问题、给谁用、哪些不做
- 原型图 — 界面与流程的初稿
- 路线图 — 版本节奏与取舍
- 验收口径 — 功能算不算做完的判据

## 在本项目中的落位（Ceph 管理平台）

- 主文档是 [`PRD-Ceph管理平台.md`](./PRD-Ceph管理平台.md)：12 项功能需求 + 11 项待决策。
- 最该写清的是「不做什么」：不代理业务 IO、不实现 CRUSH 算法、不做数据面加速 —— 否则范围会失控。
- 12 项功能里先证明两条主干——「纳管已有集群」和「异步建集群」，其余延后到 V1。
- D1~D11 未拍板前不得写成结论；验收标准要能落到测试用例编号。
