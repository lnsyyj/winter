## 1. 测试分层

| 层 | 范围 | 环境 | 能否 Mock |
| --- | --- | --- | --- |
| L1 单元 | 参数校验、状态机、幂等键、RBAC 判定、模板渲染 | 本地 | 可 |
| L2 集成 | Server ↔ DB/队列、审计写入、WS 推送、Agent 协议 | CI 容器 | 部分 |
| L3 端到端 | 新建集群、纳管、任务下发、告警闭环 | **3 节点真实 Ceph** | **不可** |
| L4 故障注入 | 断网、Agent 掉线、队列重复投递、DB 故障、凭据失效、步骤失败 | 3 节点真实 Ceph | 不可 |
| L5 安全 | 命令注入、重放、越权、凭据明文、审计篡改 | 独立安全环境 | — |
| L6 性能 | 20 集群 / 500 节点规模下的同步与页面响应 | 压测环境（可模拟节点） | 部分 |

> **红线**：cephadm / ansible / Ceph 行为不得用 mock 代替验收。本平台绝大多数严重缺陷会出在「不可逆、不幂等、会漂移」的物理操作上（权衡分析 §9），mock 测不出来。

## 2. 测试环境

| 环境 | 用途 | 配置 |
| --- | --- | --- |
| `dev` | 开发自测 | 单机管理面 + 1 节点伪 Ceph |
| `e2e` | 常驻集成 | 管理面 ×1 + 3 × CentOS Stream 9 节点（podman，每节点 ≥ 3 块盘） |
| `offline` | 离线交付验证 | 无公网，镜像经离线包导入 |
| `perf` | 规模压测 | 模拟 20 集群 / 500 节点状态上报 |
| `sec` | 安全测试 | 与 e2e 隔离 |

每个迭代开始前用快照重置 `e2e`；建集群测试会污染磁盘，必须可重建。

## 3. MVP 验收用例（P0，对应 PRD §9）

| 编号 | 场景 | 关键步骤 | 预期结果 |
| --- | --- | --- | --- |
| TC-01 | 纳管 cephadm 集群 | 填凭据 → 校验 → 同步 | ≤60s 展示健康/拓扑/容量；`managed`；默认只读 |
| TC-02 | 纳管非 cephadm 集群 | 同上 | `limited`，写入按钮置灰并说明原因 |
| TC-03 | 重复纳管 | 用同一 FSID 再导一次 | 拒绝，提示已存在的集群名 |
| TC-04 | 凭据错误 / 不可达 | 错误 keyring、错误地址 | 明确失败原因；**不落库明文**；不自动重连风暴 |
| TC-05 | 新建集群成功 | 7 步向导全流程 | `HEALTH_OK`；FSID 回写；每步有日志；等价命令可复制 |
| TC-06 | 前置检查拦截 | 制造 NTP 不同步 / 磁盘不足 / podman 缺失 | 对应检查项失败并阻止后续步骤，提示具体修复动作 |
| TC-07 | 步骤失败后重试 | 在 step-5 制造失败 → 从该步重试 | 不重复执行 step-1~4；不产生第二个集群/重复 OSD |
| TC-08 | 建集群过程断网 | bootstrap 期间断 Agent 网络 2 分钟 | 任务不丢；恢复后继续或从失败步骤重试；无重复资源 |
| TC-09 | 任务幂等 | 手动重复投递同一 `idempotency_key` | 只执行一次，第二次直接返回上次结果 |
| TC-10 | 并发互斥 | 同时对同集群提交 2 个变更任务 | 第二个排队/被拒，不并发改同一资源 |
| TC-11 | 任务取消/超时 | 在可取消步骤取消；制造步骤超时 | 状态正确；不可逆步骤不允许取消 |
| TC-12 | 状态漂移 | 平台外用 SSH 改 Ceph 配置 | Reconciler 发现漂移，UI 以真实状态渲染并标注采集时间 |
| TC-13 | RBAC 隔离 | viewer 尝试变更；operator 访问未授权集群 | 全部拒绝，审计记录拒绝事件 |
| TC-14 | Grafana 越权 | viewer 直接访问 Grafana URL / 改集群变量 | 无法绕过，只见授权集群数据 |
| TC-15 | 审计完整性 | 执行变更 → 查审计 → 尝试删改 | 记录含参数/前后快照/来源 IP；应用账号无法修改删除 |
| TC-16 | 命令注入 | 参数含 `; rm -rf /`、`$(...)`、超长、Unicode | 参数校验拒绝；绝无 shell 执行 |
| TC-17 | 凭据明文扫描 | 全流程后扫描 API/日志/审计/前端 | 0 处明文 |
| TC-18 | 任务重放 | 截获任务消息重复发送 / 过期签名 | Agent 验签失败或幂等命中，不执行 |
| TC-19 | 管理面全停 10 分钟 | 停掉所有控制面组件 | Ceph IO 不中断、`HEALTH_OK` 保持；恢复后状态自动追平 |
| TC-20 | Agent 离线 | 停某节点 Agent | 该节点任务暂停不丢；其他节点正常；告警触发 |
| TC-21 | 监控降级 | 停 VM / 日志系统 | 控制台仍可打开，显示最近同步数据 + 降级横幅，任务仍可提交 |
| TC-22 | 离线部署 | 未参与开发人员按手册在无公网环境部署 | 一次成功，命令可复制粘贴 |
| TC-23 | 3 次端到端 | 重复 TC-05 三次，其中一次含失败重试 | 三次均达 `HEALTH_OK` |
| TC-24 | 20 集群规模 | 模拟 20 集群 / 500 节点 | 总览 P95 < 3s；无同步风暴；队列无持续积压 |

## 4. 回归与发布门槛

**每次发布必跑**：TC-01、03、05、07、09、13、15、16、17、19。
**版本升级必跑**：cephadm / Ceph / OS / podman 兼容矩阵用例 + 指标名回归（防 B8 漏报）+ 模板参数解析回归（防 B4 抽象泄漏）。

发布门槛（与 PRD §9 一致）：P0 用例通过率 100%；安全用例 0 命令注入、0 明文泄露；离线部署由未参与者独立完成；管理面全停不影响数据面。

**缺陷分级**：P0 = 数据损坏/集群不可用/权限绕过/凭据泄露，阻塞发布；P1 = 核心流程不可用或状态错误；P2 = 体验与降级问题。

## 6. 已知测试难点

1. 建集群是**破坏性、耗时、不可逆**的，用例无法高频重复 → 需要环境快速重建能力；
2. 「重复执行 OSD 添加」类缺陷可能只在真实磁盘布局下暴露；
3. 状态漂移依赖时间窗口，短跑用例容易漏 → 需长稳压测（≥24h）；
4. 离线环境验证成本高，但恰恰是交付场景，不能省。
