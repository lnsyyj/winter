## 1. 背景

G4 原文是「内网 / 离线可交付」，只说了结果，没说**怎么做**。三种常见做法，只有一种能过现实条件：

| 做法 | 问题 |
| --- | --- |
| A. 目标环境直连公网 / 公共镜像站 | 绝大多数生产环境不允许，私有化客户直接否决 |
| B. 把构建搬到现场编译 | 现场无工具链、无源码依赖，且每次装出来的东西不一样，不可重复 |
| C. **有网环境预下载制品 → 搬运 → 现场远程安装** | 需要多一台制包机与一次搬运，但可重复、可校验、不依赖现场网络 |

## 2. 决策

采用 **C：三段式离线交付**。

```
① 制包（有网）        ② 搬运              ③ 远程安装（现场）
staging host    →   介质/内网文件服务器   →   安装机（跳板）--ansible--> 管理节点 / 被管节点
拉镜像·打 rpm·收 playbook    校验 sha256/digest      导入镜像·生成配置·启动·装 Agent
```

### 2.1 三个角色（均为临时，不常驻运行）

| 角色 | 要求 | 说明 |
| --- | --- | --- |
| **制包机** | 有公网或内网镜像源；**OS 与目标同版本同 minor**（CentOS Stream 9） | 一次性使用，可弃；建议用与目标同镜像的虚拟机，避免依赖漂移 |
| **安装机（跳板）** | 可 SSH 到管理节点与被管节点；有 ansible | 可用客户已有跳板机；也可退化为「把包拷到管理节点本地执行」 |
| **目标环境** | CentOS Stream 9 + podman；**零外网依赖**；无需编译工具链 | 只接收制品，不访问外网 |

### 2.2 交付物清单（BOM）

| # | 制品 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | `offline-images-<ver>.tar` + `images.digest` | 是 | 全部容器镜像，按 digest 锁定 |
| 2 | `rpms-<ver>.tar.gz` | 是 | podman / cephadm 依赖 / python 包等系统级依赖 |
| 3 | `ansible-collections-<ver>.tar.gz` | 是 | 主机前置检查与初始化 playbook |
| 4 | `agent-<ver>-linux-amd64.tar.gz` | 是 | Agent 单二进制 + systemd unit + 校验和 |
| 5 | `platform-bundle-<ver>.tar.gz` | 是 | compose / kube play 定义、配置模板、Server 二进制 |
| 6 | `checksums.sha256` | 是 | 全量校验；安装前必须先过 |
| 7 | `BOM.md` | 是 | 版本清单：组件 / 版本 / digest / 兼容矩阵 |
| 8 | 本手册 + 验收清单 | 是 | 客户签字依据 |

> 可选包与 ADR-13 的「可观测性可选装配」对应：核心包必装，日志 / 镜像仓库 / 完整监控套件可按包独立搬运。

## 3. 强制约束

| 约束 | 原因 |
| --- | --- |
| **制包机与目标 OS 同 minor** | CentOS Stream 9 是滚动发行版，minor 不一致会导致 rpm 与 podman 版本漂移（B14） |
| **安装前必须校验 sha256 + 镜像 digest** | 搬运损坏是静默的，装到一半才炸最难查 |
| **安装期允许 ansible/SSH；运行期禁止直连** | 主机初始化是一次性配置；运行期仍走 Agent 拉模式（ADR-03 / I3）。二者不能混为一谈 |
| **必须支持「无跳板机」降级路径** | 把包拷到管理节点本地执行 `install.sh`，不能假设客户一定有跳板机 |
| **上一版本离线包必须保留** | 回滚 = 重新导入上一版镜像 + 回滚 bundle，没有旧包就回不去 |
| **不依赖现场编译** | 现场出现 `go build` / `npm install` 即视为交付失败 |

## 4. 与已定决策的关系

| 决策 | 影响 |
| --- | --- |
| D6 部署形态 | **部分收敛**：确定「制包 + 搬运 + 跳板机执行」的交付模型；容器编排形态（podman kube play / compose）仍待定 |
| ADR-13 交付可控 | 体积上限的约束从「主观嫌重」变成「介质容量」：U 盘 / 内网文件服务器 / 单向导入设备决定上限，具体阈值仍待 M0 实测 |
| B1 交付成本 | 增加一台制包机与一次人工搬运——这是**明知的额外成本**，换来的是可重复、可校验、不依赖现场网络 |
| B14 OS 滚动风险 | 新增一条硬约束：制包机与目标必须同 minor，否则包能装上但运行时版本不匹配 |

## 5. 风险

| 风险 | 缓解 |
| --- | --- |
| 制包机与目标 OS 不一致，依赖漂移 | 制包脚本启动时校验 `os-release` 与 podman 版本，不一致直接中止 |
| 离线包超出搬运介质容量 | 分层打包（核心 / 可观测 / 仓库），按现场情况只搬需要的；这也是 ADR-13 可选装配的落地方式 |
| 搬运损坏导致装到一半失败 | sha256 全量校验 + 镜像 digest 校验，失败即停 |
| 客户无跳板机、网络策略只允许单向 | 降级为「本地执行 install.sh」，手册必须同时给两条路径 |
| 现场误以为「安装期 SSH」违反 Agent 架构 | 手册与安全设计都要写清「装的时候用 ansible，跑的时候不直连」 |

## 6. 什么情况下推翻

- 目标客户允许环境直连内网镜像源 → 可退化为在线安装，制包机只保留用于版本固化。
- 交付形态改为整机镜像 / OVA / 一体化硬件 → 交付模型整体替换。

推翻流程同 ADR-11 / 12 / 13：新开 ADR → 本 ADR 标 `Superseded` → 同步架构设计 §1.1/§6.1、PRD 部署目标与 FR-10、安装部署手册、TC-22、AGENTS.md I14。
