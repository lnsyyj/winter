# 架构师（Architect）

> 岗位线：**研发线** — 把想法变成能跑的代码 ｜ 原文第 **4** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

研发的「总设计师」——不天天写业务代码，负责定整体结构，本质工作是做 trade-off。

## 核心职责

- 定系统整体结构：数据库选型、服务拆分、接口设计、数据流向
- 保证系统能跑，并且撑得住未来的量级
- 重大项目的技术决策与技术评审
- 把「为什么这么选、放弃了什么」写下来，而不是留在口头

## 常见产出

- 架构设计文档
- 技术选型说明（含备选方案对比）
- ADR（架构决策记录）
- 技术评审记录

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`架构设计-Ceph管理平台.md`](./架构设计-Ceph管理平台.md)（分层、组件、链路、部署、数据模型、安全、10 条 ADR 索引）。
- 批判性分析：[`架构决策与权衡分析.md`](./架构决策与权衡分析.md)（10 条理由 / 10 优点 / 10 缺点 / 14 条弊端 / 6 种备选架构 / 推翻条件）。
- 第一原则：**控制面与数据面分离**——业务 IO 直连 Ceph，平台全挂不影响存储；违反即拒。
- 任何改动先对照「推翻条件」：若条件成立，应重写架构而不是打补丁。
