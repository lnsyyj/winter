## 1. 背景

架构设计 §5.1 的建集群时序图有三处自相矛盾：

1. 参与者画了两个 `Agent(system)` / `Agent(ceph)`，但 ADR-04 已合并为单二进制双模式；
2. `A-->>DB` 画成 Agent 直连数据库，但 ADR-03 规定 Agent 只连 Server；
3. `A->>A: ansible precheck` 让 Agent 自己跑 ansible，与「单二进制、不带运行时依赖」冲突。

其中第 1、2 条是画错，直接改。第 3 条是真正的设计问题：**建集群前的预检由谁执行**。

关键事实：**bootstrap 之前，目标节点上还没有 Agent**。所以 step-1 预检不可能由 Agent 完成——它只能从管理面推过去。

## 2. 决策

| 项 | 决策 |
| --- | --- |
| 预检实现 | **复用 `deploy/roles/prechecks`**，不另写一套 |
| 执行者 | **管理面 Runner**（ansible，经 SSH 进入目标节点） |
| 切换点 | bootstrap 之前 = Runner；Agent 上线之后 = Agent 拉模式 |
| 任务标记 | `tasks.executor` 字段：`runner` / `agent` |
| SSH 窗口 | 仅限「节点尚未纳管」期间；Agent 上线后 SSH 通道可关闭且平台不再依赖 |

### 2.1 执行者模型

```
tasks.executor = runner   → 管理面 Runner 消费，ansible 执行（SSH）
tasks.executor = agent    → 目标节点 Agent 拉取执行（mTLS 长连接）
```

两者**互斥**：同一集群同一时刻只允许一种执行者，由现有集群级 advisory lock 保证，避免「Runner 与 Agent 同时改同一集群」。

## 3. 为什么复用而不是另写

- 检查项高度重叠（OS 基线、时间同步、磁盘、podman、源与仓库可达），写两套必然漂移；
- `prechecks` 已经实现且已在部署阶段验证，复用它把「交付期」与「纳管期」的判定标准统一；
- 运维只需要记一套失败信息与修复建议。

## 4. 边界：这条 SSH 不违反 I3

I3 的原意是「**运行期**中心不直连 SSH，Agent 拉模式是唯一运维通道」。本 ADR 不改变这条，只明确一个已存在于 ADR-14 的例外：

| 阶段 | 通道 | 说明 |
| --- | --- | --- |
| 节点尚未纳管（预检、初始化、装 Agent） | 管理面 Runner → SSH/ansible | 一次性引导，节点此时无 Agent |
| Agent 上线后（所有运维、变更、升级） | Agent 拉模式 | **不得**再使用 SSH；平台不依赖 SSH 可用性 |

验收方式：Agent 上线后关闭 SSH 通道，平台仍能完成纳管、建集群后续步骤与日常运维（TC-29）。这条不通过，说明 SSH 依赖泄漏到了运行期。

## 5. 代价

| 代价 | 说明 |
| --- | --- |
| 管理面需要 SSH 能力 | 网络可达 + 一次性凭据；这是新增的攻击面，必须按短期凭据处理 |
| 凭据生命周期问题 | 建集群用的账号要不要保存？保存多久？（下一项单独定，见 §7） |
| Runner 成为新职责 | 需要处理并发、超时、日志回传；设计为**无状态、可多副本**，不引入新的单点 |
| 窗口期可能拖长 | 若 bootstrap 反复失败，SSH 通道会长期开着 → 必须有过期时间与显式关闭 |

## 6. 风险

| 风险 | 缓解 |
| --- | --- |
| SSH 凭据泄露 | 一次性/短期凭据；用后显式销毁并写审计；不入日志、不返回前端 |
| 窗口期无限延长 | 窗口默认 24h 自动失效，超时需重新授权；失败重试期间不复用同一凭据 |
| Runner 成为单点 | 无状态 + 多副本；任务本身持久化在队列里，Runner 挂了重投 |
| 有人用 Runner 绕过 Agent 做日常运维 | 只有 `executor=runner` 的任务类型可被 Runner 领取（白名单：precheck / init / agent-install）；其余任务 Runner 直接拒绝 |

## 7. 遗留（下一项决策）

**SSH 凭据怎么管理**：一次性使用即删 / 存 PG 加密可复用 / 只在内存中用完即弃。这三条对「重试友好度」和「泄露面」的取舍不同，单独定。

## 8. 什么情况下推翻

- Agent 支持「预置镜像 / cloud-init」形式的离线自注册，使节点在 bootstrap 前就能跑 Agent → 预检可回到 Agent 执行，Runner 退化为纯交付工具。
- 客户安全策略禁止管理面发起任何 SSH → 改为人工在节点执行检查脚本并回传结果（体验下降但可行）。

推翻流程同前：新开 ADR → 本 ADR 标 `Superseded` → 同步架构设计 §3/§5.1/§8、安全设计、TC-29、`AGENTS.md` I3。
