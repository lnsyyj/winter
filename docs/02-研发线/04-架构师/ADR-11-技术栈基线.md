## 1. 背景

初版设想图给定了若干技术选型，但文档一直标为「图中既定」——这是**继承**而不是**决策**，无法回答「到底定了没有」。

2026-11-15 项目负责人明确确认以下 7 项，本 ADR 将其从「沿用草图」升级为「已确认决策」，并补齐理由、放弃项与推翻条件。

## 2. 决策

| 层 | 选择 | 版本策略 | 为什么 | 放弃了什么 | 什么情况下推翻 |
| --- | --- | --- | --- | --- | --- |
| 前端 | **React + TypeScript** | 大版本随脚手架创建时锁定；`strict: true` 必开 | 生态成熟、类型安全、Grafana 面板嵌入与前端组件复用方便 | Vue（团队不熟）、服务端渲染方案（本项目不需要 SEO） | 需要多端复用（小程序 / 桌面）或强 SSR 场景 |
| 控制面 | **Golang** | 单二进制交叉编译，锁定 toolchain | 单二进制便于离线交付、并发模型适合大量任务与长连接、静态部署无运行时依赖 | Java（内存与部署重）、Python（并发与分发弱） | 需大面积复用 Python 生态（如直接调 Ansible API）导致跨语言成本反超 |
| 关系库 | **PostgreSQL** | 主版本 16（小版本策略待 DBA 定） | JSONB 存任务参数与 Ceph 原始状态、advisory lock 做集群级互斥、备份与 PITR 生态成熟 | MySQL（JSON 与锁能力弱）、SQLite（并发不足） | 规模或合规要求转向分布式数据库；**指标仍不入库** |
| 编排 | **cephadm** | 跟随 Ceph 版本矩阵 | Ceph 官方路径、容器化、无 K8s 依赖 | Rook（引入整套 K8s）、自研 SSH 编排（鉴权与审计不可控） | Ceph 官方弃用 cephadm，或客户现网全部为 Rook 部署 |
| 运行时 | **podman** | 跟随 OS 基线仓库版本 | 无 daemon、可 rootless、与 cephadm 默认容器引擎一致 | Docker（常驻 daemon 与 root 权限面更大） | 目标 OS 基线不含 podman，或 cephadm 默认引擎切回 docker |
| 初始化 | **ansible** | playbook 纳入版本控制，锁定 collection 版本 | 幂等、可审计、离线可跑、运维普遍熟悉 | SaltStack（需额外 master）、自研 SSH 批量执行 | Agent 完全接管初始化且不再需要批量配置 |
| OS | **CentOS Stream 9** | **锁定 minor 版本**，不跟随滚动 | Ceph 与 podman 官方支持矩阵内，包版本较新 | Rocky / Alma（更稳但需额外验证）、Ubuntu（矩阵外） | 滚动更新引发 Ceph / podman 兼容事故（见 B14），或客户基线强制 RHEL / 国产化系统 |

> 版本原则：所有组件**禁止浮动 `latest`**；版本号写入部署清单与 `CHANGELOG`，升级走独立提交并记录兼容矩阵（`AGENTS.md` §10）。

## 3. 为什么这 7 项先定

它们都属于**迁移成本高或不可逆**的层：换语言、换数据库、换 OS、换容器运行时，等于重写或重装。相比之下，消息队列、日志、镜像仓库这类可替换组件，晚定不会造成结构性返工。

## 5. 不在本 ADR 范围

- 消息队列（D1）、镜像仓库（D3）、日志（D4）、监控告警栈（D5）—— 仍为 `Proposed`，见 [权衡分析 §8](架构决策与权衡分析.md)。
- 认证源（D7）、纳管范围（D8）、Agent 运行账号（D9）、适用下限（D11）。
- 管理面是否 HA、是否多 Region 联邦（架构设计 §6，属演进决策）。

## 6. 风险与必须配套的缓解

| 风险 | 缓解 |
| --- | --- |
| CentOS Stream 9 滚动更新破坏兼容（B14） | 锁定 minor + 内网镜像源固定 + 升级前跑回归用例 |
| Golang 侧 Ceph SDK 弱，多数操作靠 CLI | Agent 内做 CLI 输出解析层，并为解析写契约测试（版本升级时最先坏的就是这里） |
| PostgreSQL 无专职 DBA 时易失控 | 审计表按月分区、连接数上限、备份演练纳入发布检查单 |
| 「技术栈对了」被理解成「架构也定了」 | 本 ADR 只覆盖 7 项；架构原则见 ADR-01~06 / 08~10，其余选型仍未定 |

## 7. 推翻流程

任一项需要更换时：新开 ADR 说明原因与迁移代价 → 标注本 ADR 对应条目为 `Superseded` → 同步更新 [架构设计 §4](架构设计-Ceph管理平台.md)、[权衡分析 §8](架构决策与权衡分析.md)、`AGENTS.md` §1 与 [docs/README.md](../../README.md) 索引。**不得直接改写本 ADR 的结论**（历史要留着）。
