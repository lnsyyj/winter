> **本 ADR 已被 [ADR-22](ADR-22-LDAP接入.md) 取代**：本地账号的实现约束（Argon2id、HttpOnly 会话、登录限流、初始管理员强制改密、认证与 RBAC 分离）继续有效；但「LDAP 只在 V1 预留、不实现」的结论被推翻——LDAP 改为 MVP 起即可通过配置对接。原文保留，供追溯当时的判断依据。

---

## 1. 决策

| 阶段 | 做法 |
| --- | --- |
| **MVP** | 只做**本地账号**：用户名 + 密码，服务端会话，RBAC 走平台自身模型 |
| **V1** | 预留 LDAP / OIDC **接口与数据字段**，但不实现代码 |

即：现在不接目录服务，但**把扩展位留好**，避免将来换认证源时改表结构与权限模型。

## 2. 关键实现约束

| 约束 | 原因 |
| --- | --- |
| 密码哈希用 **Argon2id**（备选 scrypt） | bcrypt 有 72 字节截断与参数偏弱的问题；Argon2id 是当前推荐 |
| 会话用 **HttpOnly + Secure + SameSite=Lax** Cookie，服务端可撤销 | 把 token 放 localStorage 等于给 XSS 送礼；服务端可撤销才能「一键踢下线」 |
| 登录限流 + 失败锁定 + 审计 | 本地账号是唯一入口，必须防爆破 |
| 初始管理员由 `post-deploy` 生成，**首次登录强制改密** | 避免出厂默认口令（手册 C6 已要求） |
| 预留字段：`user.idp`、`user.subject`、`user.external_id` | V1 接 LDAP/OIDC 时只需填充，不改表 |
| **认证与授权分离**：RBAC 不依赖认证源 | 换 IdP 不应影响角色、作用域、审计口径 |
| 密码策略与复杂度要求写进 `group_vars`，不硬编码 | 不同客户合规要求不同 |

## 3. 代价

| 代价 | 说明 |
| --- | --- |
| 企业客户早期要 SSO 时会受阻 | 需要提前告知「V1 才支持」，售前能力边界里写清 |
| 无多租户 / 多 IdP | 一套平台一套账号体系；多租户属于另一个产品命题（ADR-20 已排除极简/多租户形态） |
| 本地账号要自己承担安全责任 | 哈希、限流、会话、审计都得自己做对，不能靠 IdP 兜底 |

## 4. 为什么不让 LDAP 优先

LDAP 优先听起来更「企业级」，但代价被低估：

- MVP 要多做用户同步、组映射、连接失败降级；
- 离线环境里，平台必须能访问客户目录服务——这是**额外的网络依赖**，与「零外网依赖」的交付模型冲突；
- 客户目录服务的组结构千差万别，映射规则会变成实施期定制。

先本地、后目录，是把不确定性推后，而不是省略。

## 5. 风险

| 风险 | 缓解 |
| --- | --- |
| 首个客户强制要求 AD 集成 | 售前先确认；若确实卡单，按 ADR 修订提前实现 LDAP（预留字段已就位，改动可控） |
| 本地账号被爆破 | 限流 + 锁定 + 审计 + 强制强口令；管理面不暴露公网（默认只开 443 给管理网段） |
| 会话固定 / CSRF | 登录后轮换会话 ID；写操作校验 Origin + CSRF token |
| 未来接 OIDC 时字段不够用 | `idp/subject/external_id` 三元组覆盖主流 IdP；不足则加表而非改语义 |

## 6. 什么情况下推翻

- 目标客户群普遍要求 SSO，且本地账号被视为不可接受 → 提前实现 LDAP/OIDC，本 ADR 标 `Superseded`。
- 平台演进为多租户 SaaS → 认证模型需重做（租户隔离 + IdP 联邦），不属于本 ADR 范围。

推翻流程同前：新开 ADR → 本 ADR 标 `Superseded` → 同步架构设计 §4.1/§11、PRD D7、安全设计、API 数据模型、安装手册 C6。
