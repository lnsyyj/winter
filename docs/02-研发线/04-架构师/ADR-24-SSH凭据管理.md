> **2026-11-15 修订（[ADR-35](ADR-35-Agent预装与零SSH.md)）**：范围缩小。Agent 改为交付期预装后，**平台运行期完全不持有 SSH 凭据**——交付期的 SSH 由实施人员用 ansible 完成，凭据不进平台。本 ADR 的「内存态、不走队列、终态擦除」仍然适用于任何遗留的临时凭据场景，但已不再是主路径。

---

## 1. 决策

**平台不持久化任何 SSH 登录凭据。**

| 项 | 做法 |
| --- | --- |
| 存储 | 只在 Server 进程内存中，绑定到任务会话；**不入 PG、不入队列、不入日志、不回显** |
| 生命周期 | 任务到终态（成功 / 终态失败 / 取消 / 放弃）即擦除；平台重启即丢失 |
| 重试 | 同一会话内可复用；会话结束后重试需用户**重新录入** |
| 空闲超时 | 录入后 15 分钟内未开始执行则失效 |
| 审计 | 只记「使用了哪类凭据、目标主机、时间、结果」，**不记凭据值** |
| 首次连接 | 校验并记录主机指纹（`hosts.ssh_host_key_fp`）；这是公钥信息，允许持久化 |

## 2. 理由

平台一旦长期持有节点 SSH 凭据，B2 的爆炸半径就从「白名单内的参数化命令」扩大到「任意 shell」——攻击者拿到管理面就等于拿到全部节点的 shell，白名单形同虚设。

内存态把这一层风险直接删掉：**没有持久化的凭据，就没有「拖库即全失陷」这条路。**

## 3. 关键实现约束

| 约束 | 原因 |
| --- | --- |
| 凭据**不随任务消息走队列** | RabbitMQ 消息会落盘（durable），等于变相持久化 |
| 多副本时用**一次性 consumable token** 领取 | Runner 只拿 `task_id`，通过内部 mTLS 短连接向 Server 换取凭据；**换取即失效**，重复换取失败并告警 |
| 凭据字段在 Go 中用 `[]byte`，用后归零 | `string` 不可变、会被复制到堆各处以不可控；归零是 best-effort，需在文档中如实说明 |
| 禁止写入：`tasks.params`、审计、日志、错误栈、崩溃转储 | 任一处泄露都等于持久化 |
| 页面永不回显（包括编辑态） | 回显 = 落进浏览器缓存 / 截图 / 工单 |
| 任务终态后立即擦除，不论成功失败 | 失败任务最容易残留 |

## 4. 代价

| 代价 | 说明 |
| --- | --- |
| 隔夜重试不友好 | 长任务跨夜失败后需重新录入凭据；缓解：界面明确提示「需重新提供 SSH 凭据」，而不是报「凭据失效」让人猜 |
| 多副本实现更复杂 | 一次性 token 的交换、失效、并发保护都要做，且必须可测 |
| 无法「自动重连补做」 | 场景如「装到一半节点失联，稍后自动继续」需要人工介入 |
| 大批量预检需反复录入 | 一次会话可覆盖一批主机（凭据绑定会话而非单机），因此按会话录入即可，不必逐台 |

## 5. 与 `credentials` 表的关系

`credentials` 表**只存 Ceph 接入凭据**（`ceph` 用户 key、Dashboard 凭据等），**不含 SSH 登录凭据**。这一点必须写进表注释与代码注释，否则后来者很容易「顺手」加一个 `ssh_password` 字段。

## 6. 验收（TC-30）

| 检查 | 通过标准 |
| --- | --- |
| 全流程明文扫描 | PG、日志、审计、前端状态、错误栈、崩溃转储中 0 处出现凭据 |
| 重复领取 | 同一 token 二次换取失败并产生告警 |
| 终态擦除 | 任务结束后调试接口与内存快照中无残留 |
| 超时失效 | 录入后闲置超过 15 分钟，任务无法启动并给出明确提示 |
| 重启丢失 | 平台重启后未执行的任务需重新录入，且不产生「凭据缺失」以外的副作用 |

## 7. 什么情况下推翻

- 出现「必须无人值守批量加节点」的强需求（如 100+ 节点自动扩缩）→ 需引入短期证书/SSH CA 签发机制，而不是回退到存密码。届时应新开 ADR，把「短期凭据」而非「长期密码」作为方向。

推翻流程同前：新开 ADR → 本 ADR 标 `Superseded` → 同步架构设计 §8/§11、安全设计 §3、手册 C7、TC-30、`AGENTS.md` I5。
