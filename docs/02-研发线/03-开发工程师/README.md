# 开发工程师（前端 / 后端 / 全栈）

> 岗位线：**研发线** — 把想法变成能跑的代码 ｜ 原文第 **3** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

真正写代码、把需求变成能跑的代码的人。

## 核心职责

- 前端：眼睛能看到、手指能点的部分——页面、交互、可视化
- 后端：看不到但支撑一切的部分——API、业务逻辑、数据存取、权限校验
- 全栈：前后端都扛，小团队里最常见
- 工作流：拿需求文档 → 写代码 → 自测 → 提交测试

## 常见产出

- 可运行的功能（这是本岗位的真正交付物）
- 接口 / API 文档
- 数据库结构与服务设计说明
- 单元测试与联调记录

## 在本项目中的落位（Ceph 管理平台）

- 技术栈：后端 Go，前端 TypeScript；分层与组件职责见 [`架构设计`](../04-架构师/架构设计-Ceph管理平台.md)。
- 接口、任务状态机与表结构以 [`API与数据模型设计.md`](./API与数据模型设计.md) 为准；Agent 通信以 [`Agent-Server通信协议.md`](./Agent-Server通信协议.md) 为准；任务下发必须异步且幂等（权衡分析 B6）。
- 本平台没有独立客户端：Web 即全部交付形态，原文「客户端」相关职责并入前端。
- 代码风格、提交纪律、禁止项见根目录 [`AGENTS.md`](../../../AGENTS.md)。

## 本目录文档

- [`API与数据模型设计.md`](./API与数据模型设计.md) — REST API 分组、任务状态机、核心表结构与幂等约定
- [`Agent-Server通信协议.md`](./Agent-Server通信协议.md) — Agent 与 Server 的唯一运行期通道：传输栈、握手、三条逻辑流、消息目录、错误码、REDIRECT 迁移
