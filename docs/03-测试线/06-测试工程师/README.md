# 测试工程师（QA）

> 岗位线：**测试线** — 专门找茬的人 ｜ 原文第 **6** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

产品的「挑刺专业户」——开发想「功能实现了」，测试想「怎么把它搞崩」。

## 核心职责

- 根据需求写测试用例，验收标准即产品经理写的用户故事
- 手工或自动化执行测试，提交 bug 并跟踪修复
- 上线前回归测试，确认改一处没把别处带崩
- 参与需求评审，在动手前就问「这个异常怎么办」

## 常见产出

- 测试用例
- 缺陷报告（bug 单）
- 测试报告与回归结论
- 发布准入门槛建议

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`测试策略与验收用例.md`](./测试策略与验收用例.md)（分层策略、MVP 验收用例、发布门槛）。
- 重点不是「能不能建集群」，而是异常路径：Agent 断网、任务重复投递、并发建同一集群、审计写失败。
- 每轮发布必跑 TC-01/03/05/07/09/13/15/16/17/19（见 [`AGENTS.md` §9](../../../AGENTS.md)）。
- 测试环境要求真实 3 节点，容器化模拟不了 cephadm 的多数失败模式 —— 这是排期风险，不是测试偷懒。
