# 测试开发（SDET）

> 岗位线：**测试线** — 专门找茬的人 ｜ 原文第 **7** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

会写代码的测试——把重复点击变成自动化脚本，支撑回归测试。

## 核心职责

- 搭建自动化测试框架与测试平台
- 把手工用例转成可重复执行的脚本
- 与开发共同设计「可测试」的代码结构（可注入、可回放）
- 把自动化接进 CI，让回归成为提交的一部分

## 常见产出

- 自动化脚本 / 测试框架说明
- 测试平台文档
- CI 配置与流水线定义
- 测试数据与夹具

## 在本项目中的落位（Ceph 管理平台）

- 难点：Ceph 集群无法轻量容器化模拟，端到端回归必须依赖真实 3 节点环境，成本高。
- 现实路径：先做 API 契约测试 + 任务状态机回放（重放事件序列断言状态迁移）+ 幂等用例，再考虑端到端。
- 低成本高收益的自动化已经存在：文档链接校验、行尾空格与冲突标记检查（[`AGENTS.md` §7.3](../../../AGENTS.md)），可直接进 CI。
- 契约测试的价值：Agent 协议变更时，能在没有真实集群的情况下发现破坏性改动。
