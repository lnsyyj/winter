## 1. 导航结构

```
全局层（不依赖具体集群）
├── 总览 Dashboard        所有集群健康、容量、告警、最近任务
├── 集群管理              集群列表 / 新建向导 / 纳管向导
├── 任务中心              全部任务、进行中、失败、死信
├── 告警中心              告警事件、规则、抑制策略
├── 审计日志              检索与导出（auditor / admin）
└── 系统管理              用户、角色、凭据、组件状态、镜像仓库、系统配置

集群层（选中某集群后进入，面包屑保留全局路径）
├── 概览                  健康、容量、IO、PG、最近任务
├── 拓扑                  Host → 服务 → OSD → 磁盘
├── 主机                  节点列表、Agent 状态、前置检查结果
├── 存储资源              Pool / OSD / RGW / CephFS（MVP 以只读为主）
├── 监控面板              Grafana 嵌入（经反代鉴权）
├── 日志                  任务日志 / Agent 日志
├── 任务                  该集群的任务历史与新建任务
└── 设置                  凭据、采集周期、变更开关、Ceph Dashboard 跳转
```

**层级原则**：Region / AZ 是**筛选与分组维度**，不是独立页面层级；避免用户为了看一个集群点三层菜单。

## 3. 关键交互约定

1. **所有变更异步**：点击后不等待结果，立即跳转/展开任务详情，展示 `PENDING → RUNNING → ...`；禁止按钮一直转圈。
2. **危险操作二次确认**：删除 OSD、改副本数、停服务、集群重置等，二次确认弹窗必须显示**目标集群名 + 动作 + 参数摘要 + 影响说明**，高危动作需二次输入集群名。
3. **真实状态优先**：页面任何健康/容量数据旁必须显示「采集时间」；漂移时以 Ceph 实际状态渲染，并在旁边提示平台记录状态与之不符（对应权衡分析 B3）。
4. **区分两类分组**：界面上明确区分「管理分组（Region/AZ）」与「数据故障域（CRUSH）」，禁止用同一图标暗示容灾能力（对应 B10）。
5. **能力分级可见**：`limited` 集群的写入类按钮置灰 + 悬浮说明「该集群部署方式不受完整支持，仅可查看」，不要用隐藏按钮让用户以为是 bug（对应 B7）。
6. **失败要能自救**：任务失败页固定展示「失败步骤 / 原始日志 / 从该步重试 / 查看排障文档 / 复制等价命令」，不出现纯错误码。
7. **降级态**：监控、日志、仓库不可用时，控制台仍可打开并显示「最近同步数据 + 组件降级横幅」，不能整页白屏。
8. **等价命令可复制**：向导每一步提供「复制命令」，对应「复制粘贴就能部署」的诉求。

## 4. 状态色与文案

| 语义 | 颜色 | 文案示例 |
| --- | --- | --- |
| 健康 / 成功 | 绿 | `HEALTH_OK`、`任务成功` |
| 警告 / 进行中 | 黄 / 蓝 | `HEALTH_WARN`、`执行中 3/7` |
| 故障 / 失败 | 红 | `HEALTH_ERR`、`步骤 5 失败` |
| 不可达 / 未知 | 灰 | `unreachable · 最后同步 14:32` |

**「未知」必须与「健康」有视觉区分**：不可达不等于没问题，这是运维界面最容易犯的错。

文案用陈述句说明后果，不用「操作失败，请稍后重试」这类无信息量提示；错误提示带可行动作（去检查凭据 / 查看日志 / 重试该步骤）。
