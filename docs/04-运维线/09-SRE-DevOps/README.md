# SRE / DevOps

> 岗位线：**运维线** — 让系统别宕机 ｜ 原文第 **9** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

开发与运维的融合体——用工具和自动化让系统自己稳，核心指标是 SLO。

## 核心职责

- 定义 SLO（如 99.9% 可用）与错误预算，用数据决定能不能发布
- 搭监控、告警、自动扩容与灰度发布
- 建 CI/CD 流水线，统一开发 / 测试 / 生产环境
- 做容量规划与成本控制，把重复操作自动化掉

## 常见产出

- SLO 文档与告警规则
- 自动化流水线（CI/CD）
- 发布与回滚方案
- 容量规划与故障复盘

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`部署与监控告警方案.md`](./部署与监控告警方案.md)（管理面部署、指标 / 告警 / 日志链路、故障处置）。
- SLO 建议：管理面 API 可用性 99.9%；**不承诺**数据面可用性 —— 那是 Ceph 的 SLO，混在一起会让承诺失效。
- 告警原则：每条告警必须可行动。Reconciler 的漂移告警要区分「已知旁路改动」与「异常漂移」，否则必然被静音。
- 主要运维负担是版本矩阵：Ceph 版本 × 平台版本 × 操作系统（权衡分析 B4），升级路径要当成产品功能做。
