# 项目经理 / Scrum Master

> 岗位线：**支撑线** — 让产品更好用、更可控 ｜ 原文第 **16** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

盯进度、清障碍的人——Scrum Master 不指挥人，只服务团队。

## 核心职责

- 制定项目计划、拆解任务与排期
- 跟进进度、识别风险、协调阻塞
- 组织站会、迭代评审与回顾，维护团队节奏
- 把「卡点」消掉，而不是把压力传下去

## 常见产出

- 项目计划与排期
- 站会 / 评审 / 回顾记录
- 风险清单与依赖表
- 复盘改进项

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`项目计划与路线图.md`](./项目计划与路线图.md)（M0 / MVP / V1 / V2 里程碑、依赖、风险）。
- M0 的退出条件要写死：**纯命令行在离线环境把 3 节点集群建到 HEALTH_OK**，跑不通就不进入平台开发。
- 关键依赖是真实硬件与离线制品，排期应按「环境到位时间」倒推，而不是按人力倒推。
- 新版文章把「敏捷教练」并入本岗位：Scrum Master 职责在此承接。
