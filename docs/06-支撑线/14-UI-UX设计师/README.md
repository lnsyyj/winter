# UI / UX 设计师

> 岗位线：**支撑线** — 让产品更好用、更可控 ｜ 原文第 **14** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

UI 管「好不好看」，UX 管「用着顺不顺」——负责原型、视觉与交互流程。

## 核心职责

- 出交互原型与视觉稿，定义按钮、配色、字体、间距
- 与产品确认功能逻辑，与前端确认可实现性
- 维护设计规范，保证多页面一致
- 上线后走查实际效果，修交互缺陷

## 常见产出

- 交互原型
- 视觉稿 / 设计稿
- 设计规范（组件、色彩、间距）
- 信息架构与页面清单

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`信息架构与页面清单.md`](./信息架构与页面清单.md)（导航结构、页面清单、关键交互约定）。
- 必须区分两个概念：平台的 Region / AZ 只是管理分组，**不等于 CRUSH 故障域**（权衡分析 B10）。界面上不能只用「AZ」一个词。
- 危险操作（销毁集群、下线 OSD）需要二次确认 + 影响面预览 + 输入集群名确认，不能只弹一个「确定吗」。
- 长任务体验是核心：进度、可中断、失败重试入口 —— 建集群是分钟级操作，转圈等待等于不可用。
