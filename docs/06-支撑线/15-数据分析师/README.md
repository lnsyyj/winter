# 数据分析师（Data Analyst）

> 岗位线：**支撑线** — 让产品更好用、更可控 ｜ 原文第 **15** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

从产品数据里挖结论的人——回答「哪个按钮没人点」「用户为什么流失」。

## 核心职责

- 搭报表、定指标口径，让团队看到同一组数字
- 分析用户行为与业务指标，输出可执行结论
- 给产品与运营指方向，而不是只交一张图
- 验证改版与运营动作是否真的有效

## 常见产出

- 报表 / 看板
- 分析报告
- 指标口径说明
- 改版效果评估

## 在本项目中的落位（Ceph 管理平台）

- 分析对象是平台自身：建集群耗时分布、任务失败 Top 原因、告警噪声比、功能使用率。
- 口径必须先定清楚：什么叫「纳管成功」？任务「成功」是否包含部分成功？否则报表之间永远对不上。
- 数据来源：PostgreSQL（任务 / 审计）+ VictoriaMetrics（指标），不做跨库实时 join，走离线汇总。
- 本岗位暂不单独建档，建议第一份产出是「平台核心指标口径表」。
