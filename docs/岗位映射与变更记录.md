# 岗位映射与变更记录

> 用途：记录 `docs/` 目录所依据的岗位体系发生过哪些变化，以及**旧文档去了哪里**。
> 目录是按文章重排的，重排会导致路径变化；这份文件是唯一能还原「上一版长什么样」的地方。

## 1. 变更概要

| 项 | 旧版 | 新版 |
| --- | --- | --- |
| 文章 | [《软件行业的岗位》](https://lnsyyj.github.io/posts/software-industry-roles/) | [《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/) |
| 生效日期 | 2026-11-07（本仓库首次建档） | 2026-11-15（本次重排） |
| 分组数 | 七大岗位族 | 七条线（产品 / 研发 / 测试 / 运维 / 业务 / 支撑 / 新兴与稀缺） |
| 岗位数 | 22 | **24**（原文连续编号 1~24） |
| 岗位目录编号 | 族内顺序编号 | **直接使用原文岗位编号**（如 `04-架构师` = 原文第 4 个岗位） |

新版把编号写进目录名，是为了让「文档里说的第 N 个岗位」和「磁盘上的目录」永远对得上；代价是父目录下的编号不连续（`02-研发线/` 下是 03、04、05），这是刻意的。

## 5. 这次重排带来的实质变化（不只是改名）

1. **文档归口变了**：安装手册与 FAQ 从「实施 / 技术支持」转到「技术文档工程师」。原岗位在原文中已不存在，继续用旧目录会让归档规则失效。
2. **UI/UX 的归属变了**：从「产品与设计」转到「支撑线」。这意味着设计在这个体系里被定位为支撑职能，而不是产品决策方 —— 对评审时「谁有最终话语权」有实际影响。
3. **安全、算法、数据被归入「新兴与稀缺线」**：它们在原文里是「市场上还缺人」的岗位，不是「研发出身顺带做」。这不改变协作方式，但影响招聘与岗位描述的写法。
4. **岗位说明书补了「本项目落位」**：24 份 README 现在都写了这个岗位在 Ceph 管理平台里具体对应哪份文档、哪条风险（B1/B2/B6/B10 等），避免变成通用岗位百科。
