# 开发者关系 / 技术布道师（DevRel / Evangelist）

> 岗位线：**新兴与稀缺线** — 市场上还缺、正在冒头的职业 ｜ 原文第 **21** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

对外「交朋友」的技术人——用技术影响力换 adoption（采用率）。

## 核心职责

- 大会演讲、写技术博客、运营社区
- 维护开源项目，处理 issue 与外部贡献
- 做上手体验（onboarding），降低第一次跑通的成本
- 把外部反馈带回产品，影响路线图

## 常见产出

- 技术博客与演讲稿
- 社区内容 / 教程 / 示例代码
- 开源项目的 README 与贡献指南
- 上手工作坊材料

## 在本项目中的落位（Ceph 管理平台）

- 若平台走开源 / 半开源：Agent 协议与部署脚本最适合开放，能换取生态信任。
- 内部平台形态下，本岗位退化为「内部布道」：写内部技术号、做上手工作坊、维护内部 FAQ。
- 最有传播力的三个题材：控制面 / 数据面分离、异步任务幂等、cephadm 为什么不能中心化。
- 本岗位暂不单独建档；对外内容需先经安全评审，避免泄露内部拓扑与凭据管理细节。
