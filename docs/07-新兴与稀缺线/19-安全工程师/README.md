# 安全工程师（Security Engineer / 信息安全）

> 岗位线：**新兴与稀缺线** — 市场上还缺、正在冒头的职业 ｜ 原文第 **19** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

公司的「防盗门 + 保镖」——防入侵、做渗透、管权限和加密，靠纵深防御层层设防。

## 核心职责

- 做渗透测试与漏洞扫描，推动修复闭环
- 管权限与加密：谁能做什么、密钥怎么存
- 制定安全规范与应急响应机制
- 做安全评审，在架构阶段就拦掉高危设计

## 常见产出

- 漏洞报告与修复跟踪
- 安全规范 / 基线
- 应急响应方案
- 安全审计报告

## 在本项目中的落位（Ceph 管理平台）

- 主文档：[`安全与审计设计.md`](./安全与审计设计.md)（信任边界、mTLS、凭据加密、命令白名单、审计链路）。
- 最大风险 B2：高权限 Agent 是 RCE 放大器 —— 必须有全局熔断 + 双人复核 + 命令白名单（argv 级，不拼 shell）。
- 审计必须 fail-closed：审计写不进去就不允许执行，否则「出事查不到」比「不能操作」更糟。
- 平台账号与 Ceph 凭据分离；凭据明文零落盘，密钥用 KMS / Vault 或本地加密文件。
