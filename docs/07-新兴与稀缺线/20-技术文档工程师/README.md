# 技术文档工程师（Technical Writer）

> 岗位线：**新兴与稀缺线** — 市场上还缺、正在冒头的职业 ｜ 原文第 **20** 个岗位
> 依据：[《软件行业岗位全景图》](https://lnsyyj.github.io/posts/software-industry-job-roles/)（7 条线 / 24 岗版）

## 一句话定位

把「代码怎么用」写成人话的人——好文档是产品的门面，To B 软件尤其如此。

## 核心职责

- 写 API 文档、SDK 手册、安装与运维手册
- 维护帮助中心与知识库，让用户能自助
- 与研发确认命令、参数、版本差异，保证文档可执行
- 把 Release Notes 写清楚：改了什么、要不要动数据

## 常见产出

- API 文档 / 接口参考
- 安装、升级、运维手册
- 帮助中心 / FAQ
- Release Notes

## 在本项目中的落位（Ceph 管理平台）

- 本目录文档：[`安装部署手册.md`](./安装部署手册.md)（离线部署步骤、验收清单、回滚）与 [`FAQ与故障排查手册.md`](./FAQ与故障排查手册.md)。
- 安装手册目前是骨架，命令处留 `【TODO-Dx】` 占位 —— **选型没定之前写死命令会误导实施**，这是刻意为之。
- 文档里的命令必须与版本号对应；升级手册要覆盖「Ceph 版本 × 平台版本」的组合，否则等于没写。
- 新版文章新增本岗位，取代旧结构中「交付实施 / 技术支持」的文档职责 —— 安装手册与 FAQ 归口到这里。
