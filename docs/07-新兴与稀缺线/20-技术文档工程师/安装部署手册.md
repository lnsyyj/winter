## 1. 交付模型（三段式）

```
① 制包（有网）                ② 搬运                    ③ 远程安装（现场）
─────────────────         ─────────────────        ────────────────────────────
制包机                       U 盘 / 内网文件服务器        安装机（跳板）
拉镜像 → 打 rpm → 收 playbook   / 单向导入设备         ├─ ansible → 管理节点（装平台）
生成 digest + checksums        校验 sha256 / digest     └─ ansible → 被管节点（装 Agent）
```

| 角色 | 要求 | 是否常驻 |
| --- | --- | --- |
| 制包机 | 有公网或内网镜像源；**OS 与目标同版本同 minor** | 否，一次性 |
| 搬运介质 | 容量足够装下离线包；可校验完整性 | — |
| 安装机（跳板） | 可 SSH 到管理节点与被管节点，有 ansible；**无跳板机时可退化为管理节点本地执行** | 否 |
| 目标环境 | CentOS Stream 9 + podman；零外网依赖、无编译工具链 | 是（被管对象） |

> 边界澄清：**安装期**用 ansible / SSH 做主机初始化是一次性配置；**运行期**平台绝不直连 SSH，一律 Agent 拉模式（ADR-03）。两者不可混淆。

## 2. 交付物清单（BOM）

| # | 制品 | 必需 | 说明 |
| --- | --- | --- | --- |
| 1 | `offline-images-<ver>.tar` | 是 | 全部容器镜像 |
| 2 | `images.digest` | 是 | 每个镜像的 digest，导入后逐个核对 |
| 3 | `rpms-<ver>.tar.gz` | 是 | podman / cephadm 依赖 / python 包 |
| 4 | `ansible-collections-<ver>.tar.gz` | 是 | 前置检查与初始化 playbook |
| 5 | `agent-<ver>-linux-amd64.tar.gz` | 是 | Agent 二进制 + systemd unit |
| 6 | `platform-bundle-<ver>.tar.gz` | 是 | compose / kube play 定义、配置模板、Server 二进制 |
| 7 | `checksums.sha256` | 是 | 全量校验 |
| 8 | `BOM.md` | 是 | 组件 / 版本 / digest / 兼容矩阵 |
| 9 | 本手册 + 验收清单（§7） | 是 | 客户签字依据 |

> 可选包对应 ADR-13 的「可观测性可选装配」：核心包必装，日志 / 镜像仓库 / 完整监控套件可按现场需要单独搬运。
>
> RPM 目录需随包附带 **repodata 与 `repomd.xml.asc`（GPG 签名）**，否则节点无法开启 `repo_gpgcheck=1`，内网源就退化成「谁都能替换的目录」。

## 4. 阶段 B · 搬运与校验

### B1 · 选择介质

U 盘 / 内网文件服务器 / 单向导入设备。**介质容量决定包的分层策略**（核心 / 可观测 / 仓库）。

### B2 · 落地后先校验，再解压

```bash
# 校验必须先于任何解压与安装
sha256sum -c checksums.sha256
# 【TODO-D3】核对 images.digest 与包内镜像一致
```

> 校验失败即停，不要「先装上再说」。搬运损坏是静默的，装到一半才炸最难查。

### B3 · 落盘位置

- 安装机：`/opt/winter/bundle-<ver>/`
- 管理节点：数据卷与包分离存放，避免升级时被清理

## 6. 回滚

| 场景 | 动作 |
| --- | --- |
| 管理面部署失败 | 停止 pod / compose，保留数据卷，回滚到上一版本 bundle（**上一版离线包必须还在**） |
| Server 升级失败 | 回滚 Server 镜像；数据库 migration 需保证向后兼容 |
| Agent 升级失败 | 分批回滚二进制，Agent 需兼容 N-1 协议 |
| 离线包损坏 / 版本不符 | 停止安装，回到阶段 B 重新搬运；不要用「就地修补」的方式凑 |
| 建集群中途失败 | **不自动回滚**（不可逆，见权衡分析 B5）；按平台「失败步骤 / 清理任务」或人工清理磁盘后重跑 |
| 解除纳管 | 删除集群记录 + 删除凭据 + 吊销 Agent 证书 + 写审计；**不改动 Ceph 集群本身** |

> 最重要的回滚原则：任何情况下，控制面操作都不得成为数据面故障的来源。拿不准就先停任务下发（全局熔断）。
